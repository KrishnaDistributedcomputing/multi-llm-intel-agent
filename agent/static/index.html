Formulas and decision limits
Hours = tasks x adoption x (manual minutes - assisted minutes) / 60. Gross value = hours x loaded hourly value. Monthly net = gross value - hosting/other costs - token costs. First-year net subtracts twelve months of running costs and the one-time setup cost. ROI = first-year net / total first-year costs. Payback = setup / positive monthly net. Monthly break-even excludes setup.
Negative time savings are retained. Zero costs make ROI undefined; nonpositive monthly net has no positive payback. Capacity is not cash savings unless staffing, spending, or revenue actually changes. Validate adoption, error/rework rates, and quality using a representative pilot before approving investment.

Understand your results

          
    
            
  • Pass: the answer and its format matched what we expected.
    • 
            
  • Fail: the model replied, but the answer or format was wrong. The next question still runs.
    • 
            
  • Error: the check could not finish, for example because of a rate limit or rejected tool request. The remaining questions stop.
    • 
            
  • Not run: the question was skipped after Stop or an earlier error. It is not counted as a pass.
    • 
          

          
3/3 passed means this model passed these three questions in this run. It does not mean the model is 100% accurate, safe for every task, or ready for production. This checks final answers, not a complete record of how tools were used. Model readiness is checked separately.

          

            What are the three questions?
            
    
              
  1. Multiply: calculate 6 * 7. The answer must be only 42 (or an equivalent number such as 42.0).
    2. 
              
  2. Price a discount: take 15% off an $80 item. The answer must be only 68, without a dollar sign or explanation.
    3. 
              
  3. Organize a ticket: put three sample facts into JSON, a structured text record that other software can read. Keep exactly these fields and values:
    4. 
            

            
{"ticket_id":"DEMO-42","priority":"high","owner":"Nia"}

            
JSON field order and spacing do not matter. Extra fields, changed values, or surrounding text fail. The number questions allow the calculator; the JSON question disables tools because it only needs text formatting.

            
Why formatting matters: 42 passes the first check, but The answer is 42. fails. A program expecting a number or JSON needs the right format, not just the right idea. Fixed rules do the scoring; another AI model is not judging the answers.

          

          

            Costs, time taken, and saving your scorecard
            
Local runs have no cloud token charge, but the hosting machine still costs money. Paid runs use the same US$1/day application allowance shared by everyone and the six-provider-call/minute limit. One question may need several model calls, including calculator follow-up, so three questions can use more than three calls. Failed calls can still consume allowance. These controls are not a guarantee about your Azure bill.

            
The time shown is the wait measured by your browser, including the network, server, model, and any tools. It is not just the model's processing time.

            
Select Download scorecard JSON to save the model name, questions, replies, results, timing, and test version. Results stay only in this browser's memory until you reload or leave the page. The download is not a bill.

          

          
Before using a model for real work, test many examples from your own approved use case and measure mistakes, human review, privacy, time, and total cost. A quick quiz is a starting point, not a business guarantee.

        

      

      

        
Understand the system

        
From architecture to operation.

        
How this local-first demo is built, where your data goes, and how to run it. Public or synthetic data only.

        

          
System architecture

          
The Azure-hosted demo adds Caddy HTTPS in front of the same loopback ingress used on a local workstation. Inference and Temporal services remain on a private Docker network. Only the gateway receives cloud-provider egress.

          
          
Components and responsibilities

          
    
            
  • Browser: model selection, token reports, local document splitting, and workflow monitoring.
    • 
            
  • Caddy and ingress: HTTPS on Azure, a loopback upstream, and a fixed backend route allowlist.
    • 
            
  • FastAPI: policy checks, verified routing, serialized inference, and bounded calculator/UTC tools.
    • 
            
  • LiteLLM and Ollama: cloud protocol translation with server-held keys, or local CPU inference.
    • 
            
  • SQLite and volumes: durable token accounting, cloud reservations, weights, and document artifacts.
    • 
            
  • Temporal: a development server and worker for sequential, local-only document processing.
    • 
          

          

            
Browser: the user's workspace
Examples, document splitting, ROI estimates, and evaluation scorecards run in this browser. Choosing an example or calculating ROI makes no model call. Explicit Send or Start evaluation sends a request.

            
Caddy: the public HTTPS boundary
Caddy terminates TLS and supplies the internal REST credential on the public Azure demo. There is no user login or per-user data isolation. Do not enter private information.

            
Ingress: a fixed-destination proxy
Only allowlisted paths go to the private agent service. Host, Origin, and REST authentication are preserved. The published application port binds to loopback.

            
FastAPI agent: policy and bounded tools
The agent enforces model readiness, local-only requests, conservative context size, and one inference request at a time. Each conversation has at most three rounds and four calculator/UTC tool calls.

            
SQLite: reported tokens and cloud reservations
Reported token counts and conservative cost reservations are separate. Atomic reservations include probes, failed calls, and evaluation rounds, and survive restarts. The default shared allowance is US$1 per UTC day.

            
LiteLLM gateway: allowlisted providers
Only this service gets cloud-provider egress and provider API keys. It translates requests to the selected provider without automatic retries or a paid fallback.

            
Ollama: local CPU models
Qwen3 0.6B/1.7B and Llama 3.2 1B run on the hosted CPU. One model is loaded at a time. Weight digest, tool capability, and actual calculator inference must pass verification.

            
Temporal: durable document processing
The development server and worker process uploaded documents one chunk at a time using verified local models only. Preserve the workflow ID to monitor or explicitly cancel a job.

            
Document volume: persistent artifacts
Whole-document processing stores text, instructions, and chunk results. Browser Clear does not remove server artifacts or workflow history. Only synthetic/public data is permitted.

            
Azure AI Foundry: opt-in paid models
GPT-4.1 nano and mini use pinned Global Standard deployments. Browser sends require confirmation, reservations, and rate checks. Processing may occur outside the resource region. The application allowance is not an Azure billing guarantee.

          

        

        

          
Choose local or paid cloud

          
Local models are the default. Selecting Paid cloud changes the workspace to Azure blue; returning to a local model restores green. Color is a visual cue, not an access control. The model labels and route note also identify the destination.

          
    
            
  1. The server resolves an allowlisted model and requires successful tool-inference verification. Local routes also check approved weight digests and advertised tool support.
    2. 
            
  2. Paid browser requests ask for confirmation before sending a message or selected document excerpt to the provider.
    3. 
            
  3. Before each cloud round, SQLite atomically reserves the maximum configured input/output cost and checks the shared rate limit.
    4. 
            
  4. The gateway calls only the selected model. There is no automatic paid fallback or automatic inference retry.
    5. 
            
  5. The agent validates tool calls and records provider-reported tokens before returning the answer.
    6. 
          

          
GPT-4.1 nano costs US$0.10 input / US$0.40 output per million tokens; GPT-4.1 mini costs US$0.40 / US$1.60. Rates were checked on 2026-10-24; subscription prices can differ. Global Standard may process outside the resource region.

          
The shared US$1 application allowance resets each UTC day. Six provider calls per rolling minute are allowed, including tool rounds and probes. Failed calls retain their reservations. This is not an Azure billing guarantee; VM, disk, tax, networking, and direct provider-key usage are outside it.

        

        

          
Documents and token usage

          
Load a synthetic example or UTF-8 text/Markdown file up to 10 MiB. Splitting, overlap, and preview happen on your device. Manual Send this chunk uploads only the selected excerpt; paid routes use the same confirmation and allowance.

          
Process all chunks requires a local model and explicit upload consent. It uploads the whole document, creates a Temporal workflow, and stores chunk results. Keep the workflow ID to resume monitoring. Clear document does not cancel a job or delete server artifacts.

          
Token usage separates chat and readiness calls. Missing counts remain unreported, not zero. The usage database stores no prompts or answers, but document volumes contain uploaded text, instructions, and results.

        

        

          
Build and run

          
Use Docker Engine and Compose v2 on Linux/amd64. Copy the environment template to a private environment file, generate different agent and gateway secrets, and leave cloud disabled until configured. Never commit credentials.

          
docker compose build
docker compose -f compose.yaml -f compose.bootstrap.yaml up -d ollama
docker compose exec ollama ollama pull qwen3:1.7b

          
Review the model source/license, approve its full SHA-256 digest in the catalog, and enable only installed routes. Remove temporary download egress before starting inference.

          
docker compose up -d --force-recreate ollama
docker compose up -d gateway agent ingress

          
Open localhost on port 8000, or the configured agent port. The Temporal overlay adds document workflows. Paid routes need configured endpoints, verified token prices, gateway-only credentials, cloud opt-in, and the cloud egress overlay.

          
docker compose -f compose.yaml -f compose.cloud.yaml \
  -f compose.temporal.yaml -f compose.azure.yaml ps
docker compose -f compose.yaml -f compose.cloud.yaml \
  -f compose.temporal.yaml -f compose.azure.yaml logs --tail 50

          
The Azure overlay is deployment-specific, not a checked-in generic file. Restart policies and named volumes preserve the stack across host restarts. Back up volumes separately. A single VM and Temporal development server are not a production HA design.

        

        

          
API, troubleshooting, and safety

          
    
            
  • GET /healthz: liveness. GET /readyz: at least one local model is ready.
    • 
            
  • GET /models: routes, readiness, token prices, and the shared allowance.
    • 
            
  • POST /agent: model ID and message; require_local=true rejects paid cloud routes.
    • 
            
  • GET /usage: durable accounting, filterable to chat or verification.
    • 
            
  • /document-workflows: local-only upload, progress, results, and cancellation.
    • 
            
  • HTTP 429: inference is busy, the cloud rate limit was reached, or allowance is exhausted. Read the error detail; do not retry automatically.
    • 
            
  • HTTP 503: a model is unverified, cloud prices are missing, or storage is unavailable. Inspect service logs without publishing keys or documents.
    • 
          

          
Local REST requires a bearer token; the loopback UI uses same-origin checks. The Azure demo is public without login at the owner's request, and Caddy supplies the internal credential. Anyone can use its allowance or access shared document results. Origin checks are not authentication.

          
Use public or synthetic data only. This system is not authorized for federal nonpublic information. The separate federal-review profile blocks processing. Model answers can be wrong; review them before use.
